# Изменение веб-клиента

Страницы рендерит сам `api` (`internal/adapters/web`): Go-шаблоны + htmx.
Отдельного фронтенд-приложения нет.

## Устройство

| Файл | Ответственность |
|---|---|
| `web.go` | сборка обработчика, имена шаблонов, маршруты |
| `client.go` | каталог, меню, оформление и отмена заказа |
| `partner.go` | вход и кабинет заведения |
| `partner_session.go` | cookie-сессия и прослойка `requirePartner` |
| `render.go` | рендеринг и перевод доменных ошибок в страницы |
| `funcs.go` | функции шаблонов |
| `templates/*.html` | разметка |

## Правила, которые легко нарушить

**Имена шаблонов — с префиксом.** Страницы объявляются как `page:menu`,
фрагменты — `partial:order-detail`, и вызываются по константам из `web.go`.
Префикс существует не для красоты: `ParseFS` регистрирует каждый файл ещё и под
именем файла, поэтому обращение к `"menu.html"` не падает, а **молча отдаёт
пустую страницу с кодом 200**. Новый шаблон добавляется в список
`assertTemplatesDefined` — тогда промах виден при старте сервиса.

**Ошибки — через `renderError`.** Никаких `http.Error` с `err.Error()`:
доменная ошибка несёт текст для человека и код, по которому берётся HTTP-статус
(тот же `problem.StatusFor`, что и у JSON API). `http.Error` превратил бы
`OUT_OF_STOCK` в «внутреннюю ошибку» и потерял бы весь смысл кодов.

**Сценарий обязан работать без JavaScript.** htmx — только улучшение. Поля
форм именуются по смыслу (`qty_<артикул>`), а не по индексу, чтобы серверу не
требовалась синхронизация индексов скриптом. Проверка: отключить JS и пройти
сценарий.

**Фрагмент не должен быть документом.** Если хендлер отвечает на htmx-запрос
(`isHTMX(r)`), он рендерит `partial:*` без `<!DOCTYPE html>`. Иначе целая
страница вложится внутрь `<div>`.

**`restaurant_id` в кабинете — только из сессии.** `partnerFromContext(ctx)`,
никогда не `r.PostFormValue("restaurant_id")`. В формах панели такого поля нет
вовсе — см. ADR-0004.

**Деньги форматирует `money`** (это `domain.FormatKopecks`), а не арифметика с
float в шаблоне: витрина обязана округлять так же, как чек.

## Новая страница

1. Шаблон с `{{define "page:<имя>"}}`, включает `layout:head`, `layout:header`,
   `layout:footer`.
2. Константа имени в `web.go` + строка в `assertTemplatesDefined`.
3. Типизированная структура данных страницы (не `map[string]any`).
4. Хендлер: разбор запроса → use case → `h.render(...)`; ошибки — `renderError`.
5. Маршрут в `Mount`. Если страница относится к кабинету — внутрь группы с
   `h.requirePartner`.
6. Тест в `web_test.go` через `httptest`: код ответа, ключевой текст на
   странице, а для изменяющих операций — что состояние поменялось именно у
   заведения из сессии.

## Проверка

```bash
go test ./internal/adapters/web/...
make lint
make up && curl -s localhost:8080/<путь> | head -40
```

Пустой или подозрительно короткий ответ при коде 200 — почти всегда неверное
имя шаблона.
